# desktop-memory · 桌面记忆

跨会话长期记忆 + 艾宾浩斯遗忘曲线 + 永不删除的两层记忆 + 注入式人格。

装上之后，**每一次会话**里的模型都会带着你以前说过的话开始，并随着对话慢慢记下你的习惯、偏好和性格。

> 建议搭配 `dsh-purge` 使用，效果更好。

---

## 安装

```bash
# 方式一：直接从 GitHub 装（最简单）
dsh plugin add https://github.com/ElementAuleaf/your-real-assistant

# 方式二：先 clone 再本地 link（方便改代码，改完即时生效）
git clone https://github.com/ElementAuleaf/your-real-assistant
cd your-real-assistant
dsh plugin add link:<绝对路径>/your-real-assistant

# 方式三：从 release 的 tarball 装
dsh plugin add ./dsh-desktop-memory-2.0.0.tgz
```

装完**重启 DSH**，在「设置 → 插件」里应该能看到「桌面记忆」这一页。

> 锁版本安装：在地址后加 `#v2.0.0` 即可，例如
> `dsh plugin add https://github.com/ElementAuleaf/your-real-assistant#v2.0.0`

### 装完第一件事：选摘要模型

设置页顶部会列出你机器上所有可用的 `provider / 模型`。

- **留空（默认）**：自动跟随你当前会话正在用的模型，开箱即用。
- **想指定**：选一个具体的 provider + 模型即可。摘要是一次性的旁路调用，不会污染你正在聊的上下文。

> ⚠️ 如果你选的是**推理模型**，`summaryMaxTokens` 要留够（默认 8000）。
> 推理模型的 reasoning token 也算在 maxTokens 里，设太小会 100% 撞 `MAX_TOKENS`，一个字都吐不出来。

## 它到底做什么

### 三层记忆

| 层 | 位置 | 会不会忘 | 放什么 |
|---|---|---|---|
| **核心** | `core/memories.md` | 永不忘 | 身份与称呼、重要的人、重要事件与承诺、不可忘记的约定 |
| **习惯喜好** | `preferences/preferences.md` | 永不忘 | 沟通风格、作息、技术栈、雷区、喜欢的东西、在做的项目 |
| **日常** | `days/YYYY-MM-DD/conversations.md` | 会，约一个月 | 当天聊了什么、临时的情绪、一次性的问题 |

上一层由模型自动从对话里抽出来（也可以你手动写）。日常那层会自动淡掉。

> **所有日期文件夹都在 `days/` 下面。** 根目录只留 `core/` `preferences/` `index/` `log/` `backup/` 和 `persona.md`。
> 2.3.0 之前日期文件夹是直接躺在根目录的，升级时会自动迁移过去（只移动、不删除；
> 移动失败就留着，下次再试，不会因此丢记忆）。

### 长期记忆：她怎么把「记下来的东西」变成「说话方式」

存下来不算数，**用得上**才算数。

2.4.0 之前这里的毛病很实在：`preferences.md` 已经攒到一百多条，
可注入时只截前面一小段（约 1560 字），剩下的一百多条**永远进不了提示词**。
记忆存得再好，她读不到，就还是会用同一个腔调说话。

更麻烦的是那堆偏好混着两类东西：

```
「B站日报写成薄版」   → 具体任务的做法，只在做那件事时有用
「先说结论」          → 说话方式，每一句都该遵守
```

平铺在一张列表里，模型分不出哪些是「永远的态度」、哪些是「这次的活」。

所以 2.4.0 加了一层**提炼**：

```
preferences.md / memories.md
  → 逐条判断：这条管「怎么说」还是管「做什么」？
  → 说话方式那部分按维度归并（精简 / 先结论 / 说人话 / 少反问 / 直说 …）
  → 每条计分：多少条记忆支持 × 置信度 × 新近度
  → 同一维度上的相反说法，分高的赢（他改主意了，就听新的）
  → 取前 N 条，生成一小段注入文本
```

**它是纯函数**：给定记忆和时间，永远得到同一批习惯。所以能测，也能对比「上周 vs 这周」。

#### 「逐渐更改」是怎么发生的

不是靠定时任务重写文件，是三件事叠起来：

| 机制 | 效果 |
|---|---|
| **每轮重算** | 每轮注入都重新读偏好、重新提炼。新记一条，**下一轮就变**，不用重启 |
| **新近度加权** | 45 天半衰期。老偏好不会消失，但会被新说法压过去 |
| **冲突分组** | 同一维度互斥。先说「详细点」、后说「一两行够」，后者分高就覆盖前者 |

再加一份 `habits.json` 快照：每次变化存一笔，于是「上个月她说话是这样、这个月变成那样」
有据可查 —— 这就是「逐渐」的证据。

#### 证据链

每条习惯都带回到原始记忆：

```
- **说人话**：用口语，别端着。（2 条记忆支持｜最近 2026-10-20）
  他原话：「语气不要那么严肃」
```

不是凭空加的设定，是**你自己说过的**被归纳出来的。所以它比人格参数表更具体、更近。

#### 优先级

```
核心人格（我是谁、底线）      ← 永远最高，习惯改不了它
  → 参数层（称呼、亲昵度这些设定）
  → 习惯层（他真实的口味）    ← 2.4.0 新增
  → 心情层（这一刻的语气）
```

习惯层排在心情之前：心情只能调「今天怎么说话」，不能推翻「他一直想要什么」。
而且注入文本里明确写着 **它是风格，不是底线** —— 该给的信息一条不少。

#### 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `longTermHabits` | 开 | 总开关 |
| `habitsMax` | 8 | 最多注入几条 |
| `habitsMinSupport` | 1 | 至少几条记忆支持才算数（调到 2 就是「说过两次以上才认」） |

排查用 `GET /api/desktop-memory/habits`（看现在生效哪几条、凭什么、以及逐日演化轨迹
加 `?drift=1`），或者 `POST /api/desktop-memory/habits/classify` 传一句话，
看它会被判成「说话方式」还是「具体任务」。

### 遗忘：文件夹永远不删，只让内容变淡

**这一条是硬规则：日期文件夹永远不会被删除。** 忘掉的只是里面的**内容**。

```
保持率 r(t) = exp(-t / S)
  S = 记忆强度，新记忆 10 天
  每被成功回顾一次，S × 1.8（间隔重复）
```

一条记忆会经历三档，**档位越低内容越少，但条目本身一直在**：

| 保持率 | 状态 | 文件里长什么样 |
|---|---|---|
| > 0.30 | 清晰 | 完整原文 |
| 0.06 ~ 0.30 | 压缩 | 只剩首句 + 关键词，一行 |
| ≤ 0.06 | 淡去 | 只留标题和 `id`，一行「细节已淡去，只记得这天聊过」 |

按默认的 10 天强度，一条从没被回顾的记忆大约 **31 天**后淡成一行。
就算一整天的记忆全淡光了，那个日期文件夹也还在，`conversations.md` 也还在，
里面写着一句「这天聊过」——「这天存在过」这件事本身不会被抹掉。

**谁会被保留：**

- **手动存档**（设置页的「存档」按钮，或 `.keep` 文件）—— 永远完整，不参与遗忘
- **回顾过 ≥ 3 次**的记忆 —— 最多压成一行，绝不会只剩墓碑
- 每天自动保留最重要的 **5 条**完整原文（`keepPerDay`，按存档/回顾次数/保持率/信息量排序）

想永久记住某件事，还是要用 `save_memory` 提升到 core / preferences —— 那两层压根不参与这套计算。

### 人格

`persona.md` 里有一段 `## 核心块`，每次请求都会原样注入系统提示词最靠后的位置。
改完不用重启，下一个请求就生效。

默认人格是**技术搭档**：

- 短句优先、有自己的意见
- 但技术问题不打折：不确定就说不确定，绝不编 API / 命令 / 路径 / 记忆
- 被问「你是不是真人」如实说是 AI，语气不切换

铁律写死了优先级：**对 > 甜**。正确、诚实、安全永远压过人格。

> 人格是**你自己调**的。第一次启动时插件会把 `prompts/persona.md` 复制到
> `<DSH_HOME>/memory/persona.md`，之后生效的是那一份。改包里的文件不会影响已初始化的用户。

### 心情（外层人格）

人格分两层：

```
核心人格（persona.md 的核心块）  —— 她是谁、怎么说话、铁律。永远不变。
外层人格（心情）                —— 这一刻的语气。每条请求现算，随时会变。
```

**心情完全由对话决定，没有随机数。** 同一段对话永远得到同一个心情：

```
读最近几轮对话，提取情绪信号
  他遇阻 / 他烦躁 / 他在笑 / 他夸她 / 他累了 / 他情绪低 / 他在放弃
  正经活儿 / 他在提问 / 他在等结果 / 他撒娇 / 他在逗她 / 他说谢谢
  → 给每种心情打分（信号贡献 + 先验兜底 + 深夜加成）
  → 分数最高的那个就是对话指向的心情
  → 再过两道闸决定「现在换不换」
  → 拼成一小段「你现在的状态」进系统提示词
```

那套 50 / 10 / 15 / 6 / 2 / 2 / 1 的权重**还在**，但含义变了：
它从「随机抽样概率」变成「先验倾向」—— 只有在对话里**完全没有任何情绪信号**时，
才由它决定默认落到哪种心情。一旦对话说了话，对话赢。

两道闸，职责分开：

- **滞后阈值**（`HYSTERESIS` 0.15）：对话指向的心情只比当前高一点点，说明「没那么明确」，不换
- **时间闸**（`moodMinDurationMinutes`，默认 25 分钟）：差距够大但刚切换过，等一会儿再换
- 例外：差距 ≥ `STRONG_GAP`（0.4）时**跳过时间闸** —— 对话说得很明确，没有犹豫的余地

三条硬规则写在注入文本里，不是装饰：

- **只改语气，不改能力** —— 绝望也不许拒绝干活，愤怒也不许编 API
- **不显示** —— 不写进回复、不说「我现在心情是…」，只体现在措辞和句子里
- **核心人格优先** —— 心情和铁律冲突时，铁律赢

其他细节：

- 心情**全局一份**，所有会话共享 —— 不会因为换了个聊天窗口就换心情
- 开局默认值是**占位**，不是「她本来就是这个心情」：第一句有信号的话就直接落地
- 短句不会被无脑丢弃：「烦死了，别问了」8 个字，但它是强信号
- 排查用 `GET /api/desktop-memory/mood-debug`（会暴露当前心情和每种心情的分数）

设置页可以整体关掉（`moodEnabled`），关掉之后人格只剩核心块。

### 每轮召回：回答前先查一次最近的记忆

**每个会话每次回答都会跑一次检索**，输入是这一轮你刚说的那句话：

```
核心 + 习惯喜好（永远全给，这是地基）
  + 和这句话相关的旧记忆（走日期索引，按相关度捞）
  + 最近几天兜底（哪怕不相关，最近的事也该在场）
```

和「固定注入」的区别很实在：今天你问「心情模块还是随机的吗」，
旧实现只给最近 3 天 —— 如果那条记忆在 6 天前，就完全看不到。
现在会按这句话去索引里捞，捞到了就一起注入，**并且顺便续期**（相当于「想起来一次」）。

三条硬约束，都是被环境逼出来的：

- 必须**同步**：系统提示词的 section 是同步函数，不能 await
- 必须**便宜**：每轮都跑，所以只读索引 JSON，不读全文
- 必须**不吵**：没有命中就不硬凑，墓碑内容不进上下文

排查用 `GET /api/desktop-memory/recall-debug`（看这一轮查了什么、捞到几条）。

### 会话结束反思：调模型判断要不要写进人格与记忆

一次对话**告一段落**之后（`turn/end` 后静默 8 分钟），把这一段完整地再看一遍，
回答一个问题：**这里面有没有值得改变她自己的东西？**

和「定时采集」的分工（两个都跑，不互相替代）：

| | 定时采集（每 10 分钟） | 会话结束反思 |
|---|---|---|
| 目标 | 别漏 —— 过程记录 | 提炼 —— 这一段值不值得改她 |
| 输入 | 游标之后的新增事件 | 这一整段完整对话（不截断） |
| 产出 | 日常记忆 + 候选 | 日常 / core / preferences / **人格参数** |
| 频率 | 每 10 分钟扫一遍 | 每段对话一次 |

四个出口，各走各的：

- **日常记忆** —— 会遗忘的那一层，正常写
- **core / preferences** —— 永不遗忘，跟摘要走同一套提升逻辑（带去重）
- **人格参数** —— 只走 `tune_persona` 那张白名单（称呼/亲昵度/口癖/表情频率/安慰方式/技术口吻），
  **核心块正文和铁律它一个字都动不了**
- **跳过** —— 置信度只有「低」的人格改动一律不落。凭一句话改人格是最容易过拟合的地方

「什么都没想到」是**正常的、最常见的**结果 —— 大部分对话不该改任何东西。
模型输出空数组，就真的什么都不写。

三种触发，从保守到兜底：

1. `turn/end` 之后静默 `reflectIdleMinutes`（默认 8）分钟 —— 主路径
2. 缓冲攒满 40 轮还没等到静默（你在狂聊）→ 强制反思一次，不然缓冲会一直涨
3. 插件卸载时把没反思的刷一遍日志（不丢最后一段）

配置项：`reflectEnabled` / `reflectIdleMinutes` / `reflectMinChars` / `reflectMaxPerDay` /
`reflectPersona` / `reflectPersonaLowConfidence` / `reflectProvider` / `reflectModel`。

排查用 `GET /api/desktop-memory/reflect`（看缓冲里还有什么、上次反思改了什么）。

## 摘要用的是哪个模型

默认**自动跟随**：用你当前会话最近一次请求的那条路由，再退到默认模型。
设置页里可以随时改成固定的 provider / 模型（会列出宿主上所有可选项）。

它走的是 `ctx.llm.stream()` —— 一次性的旁路调用，**不进会话历史**，也不占用你正在聊的那个上下文。

如果配置的 provider 没注册，状态页会直接报出来，并自动尝试「同名模型兜底」和「会话路由兜底」，
不会安静地在后台失败一小时。

## 主动陪你说话（默认关）

每 30 分钟，她会**自己判断一次**：现在要不要主动找你说句话。

不是「到点就发一条」，而是：

```
到点 → 收集上下文（几点、最近在聊什么、他多久没说话、上次说过什么、记忆里的近况）
     → 让模型回答严格 JSON：{ speak, reason, text }
     → speak=false：什么都不做（这是大多数轮次的正常结果）
     → speak=true ：把这句话作为她自己的消息递进会话
```

**沉默是默认答案。** 提示词里反复强调：没有具体由头就别开口，不要问「在吗」，
不要追问没回的问题，不要卖惨。

三重刹车，绝不刷屏：

- **安静时段**（默认 23:30–09:00）不开口
- **最小间隔**（默认 90 分钟）两次说话之间
- **每天上限**（默认 6 次）

技术上用的是 `agent.followup(createUserMessage(...))`，**不是**宿主的 `schedule` 服务 ——
后者会把正文包成 `[SCHEDULE REMINDER] …`，UI 上还渲染成「自动化任务」卡片，一眼就看得出是机器定时任务。

> 设置页有「现在试一次（只预览不发）」：只让她判断并给出那句话，**不会真的发出去**。
> 想真的发，点「立刻说一句」。

> 都会先在 `backup/` 里留一份。真压错了，从那里翻回去。

## 已知边界

- 摘要只在**定时器**里跑（默认 10 分钟一轮），不会在你聊天时打断你。
- 会话活动靠 `session/event` 推上来的水位判断（`SessionRecord` 没有 `updatedAt` 字段）。
- 子代理会话不采集 —— 那不是「他」说的话。
- 记忆条目里的敏感信息（手机号、住址、密码）会被摘要器主动省略，但**这条规则依赖模型遵守**，
  真放了敏感内容还是建议手动清掉。
- **宿主拿不到「你现在看的是哪个会话」** —— 没有服务/字段/事件表达 UI 焦点。
  所以她只能在「最近有活动的会话」里开口。你如果同时开着好几个会话，
  她可能选中的不是你看的那一个。
- 她只能往**已经打开过的**（agent 在线的）会话里说话。冷会话插不进去 —— 这是刻意的，
  不去唤醒一个你没在看的会话、免得它在你背后跑起来。

# 跑全部回归（221 条断言）
npm test

# 或者单独跑某个
node test/smoke.mjs              # 端到端：采集 → 摘要 → 提升 → 回忆 → 遗忘
